# 飞书原位编辑与复习材料

仅在用户要求操作飞书知识库、制作测试或插入视觉内容时读取相应章节。

## 飞书原位编辑

### 身份与文档归属

- 默认通过用户已登录的飞书会话，以用户身份创建或编辑文档。
- 不要使用机器人、企业应用或租户身份创建用户无法直接编辑的文档，除非用户明确要求该方式。
- 用户说“以后都以我的身份创建文档”时，将其视为后续飞书创建任务的明确偏好；实际操作前仍要确认当前登录会话可用。

### 目标解析

写入前依次确认：

1. **知识来源**：内容依据哪篇或哪些笔记。
2. **目标文档**：是修改原笔记、更新刚创建的测试文档，还是新建文档。
3. **插入位置**：对应章节标题、段落之前或之后。
4. **交付形态**：正文、表格、流程图、测试题或组合形式。

优先从会话上下文、知识库目录和文档标题中解析，不重复询问已经给出的信息。存在两个合理目标且误写代价较高时，才向用户确认。

### 写入与验证

- 修改既有文档时优先原位编辑，不复制整篇，不创建同名文档。
- 富文本编辑器先做极小写入探针并目视确认落点，再写入大量内容。
- 核心知识、重点提醒和易错点使用飞书原生高亮块（Callout），不要用普通引用段落冒充。高亮块应包含浅色背景与边框、左侧图标、加粗标题；块内需要列举多个条件时使用编号或项目列表。推荐语义映射：`🔑 核心知识`、`💡 重点提醒`、`⚠️ 易错点`。
- 高亮块只用于真正需要记忆、执行或避错的内容，避免每节重复堆放导致重点失焦。
- 写完后同时验证：标题未重复、原文未被覆盖、内容位于目标章节、图片已显示、云端已保存。
- 写完后抽查每类高亮块，确认背景、边框、图标、标题和块内列表均已实际渲染，而不是显示为 Markdown 符号或普通文本。
- 若写错位置，先恢复误改内容，再写入正确目标；不要把恢复工作留给用户。
- 最终提供准确的飞书文档链接，并用一句话说明插入位置。

## 流程图

- 流程图内容必须来自笔记原文，阶段名、先后关系和交付物不能凭空增加。
- 三至六个主要阶段优先使用横向或蛇形流程；阶段更多时按里程碑分组，避免字号过小。
- 每个阶段最多展示：阶段名称、关键动作、核心交付物。细节继续保留在正文中。
- 视觉上区分阶段，但控制颜色数量；确保中文在正常缩放下可读。
- 插入位置优先放在对应章节标题或“标准流程”小节之后、详细说明之前。
- 插图后保留文字版流程，保证搜索、复制与无障碍阅读。

## 复习测试

### 依据与覆盖

- 先通读目标知识库范围，再建立“知识点—题目”映射；不要只围绕开头几节出题。
- 每题都能追溯到具体核心知识点。解析说明正确原因，并解释干扰项为什么不成立。
- 基础题、难题和易错陷阱题按用户比例分配；比例无法整除时，以总题量下最接近的整数分布为准，并避免把“措辞刁钻”当作难度。

### 两种交付方式

1. **试卷模式**：先完整输出全部题目，在文末或最后一页统一放答案与解析。答案不紧跟题目。
2. **互动练习模式**：题目下保留可输入的答题区，并使用飞书可用的折叠块、详情块或等效结构隐藏答案。先实际测试用户能输入、答案能展开，再批量制作。不要声称实现了自动判题，除非确实存在并验证了该能力。

### 飞书文档可答性

- 通过用户身份创建文档，确保用户拥有编辑权限。
- 答题区使用普通可编辑段落、表格单元格或飞书原生表单能力；不要把整份试卷做成不可填写的图片。
- 如果平台能力只能实现“点击展开答案”，明确称为答案揭示，不包装成自动提交或自动判分。
